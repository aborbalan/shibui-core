Hito 1

Cimientos e ingestión

F0

Cimientos + modelo de datos

hecho

Esqueleto del paquete y tooling de test desde cero. El núcleo de esta fase es el modelo de datos del contrato: la forma normalizada con la que hanko representa internamente un componente leído del CEM. Todo lo demás cuelga de aquí.

✓ Hecho ▸ modelo src/core/contract.ts + spec · tsconfig · Vitest + primer test · ADR-001 / ADR-002

✓ Mergeado ▸ en main vía PR #502

F1

Ingestión del manifest

hecho

Lectura del custom-elements.json (CEM) → modelo de datos interno. Aquí se define el borde de ingestión, donde más adelante encajarán los adapters de formatos no estándar.

✓ Hecho ▸ ingestCem (CEM → ContractSet) + parseType · src/ingest/ · spec ingest.md · tests

✓ Verificado ▸ type-check limpio · 13 tests pasan (3 ficheros) · vitest run desde repo principal

F2

Smoke · primer sello

pendiente

Validación mínima end-to-end sobre 10 → 99 componentes de shibui-ui. Emite el primer sello, aunque sea básico. Responde la pregunta clave: ¿el flujo manifest → verificación → sello funciona a escala real?

★ valida la tesis del producto
Primera tanda acordada

F0 + F1 + F2 se abordan juntas. Llegar a un sello real sobre componentes reales es el hito que justifica seguir invirtiendo en las capas profundas del Hito 2.

Hito 2

Capas de verificación

F3

Contrato

pendiente

Verifica props / eventos / slots / métodos declarados contra el runtime. Aquí vive la regla de oro (ausencia ≠ incumplimiento) y los niveles Floor → Conformance → Strict del ADR-001.

Entregable ▸ checks de contrato + spec checks-contract.md

F4

Accesibilidad (a11y)

pendiente

axe + navegación por teclado + foco + ARIA. Pruebas universales: aplican a cualquier componente, declare lo que declare su manifest.

Entregable ▸ suite a11y + spec checks-a11y.md

F5

Resiliencia

pendiente

Props basura / vacías, SSR, RTL. El componente no debe romperse ante entradas adversas. También universal, no depende del contrato.

Entregable ▸ suite de resiliencia + spec checks-resilience.md

参
Hito 3

Reporte y desacople

F6

Trust Report + gates de CI

pendiente

Reporte de confianza (JSON + HTML) que declara procedencia y cobertura del sello. Gates que fallan el build cuando un componente no cumple su nivel exigido.

Entregable ▸ Trust Report + integración CI + spec trust-report.md

F7

Desacople + publicación npm

pendiente · diferida

Garantizar que el core no depende de shibui y publicar @shibui-ui/hanko como paquete independiente. Diferida hasta validar el uso local.

Entregable ▸ paquete publicable + verificación de genericidad del core
