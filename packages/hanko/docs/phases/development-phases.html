F3

Contrato

hecho

Primera capa que mira el runtime: compara lo declarado contra el elemento vivo. Aquí viven la regla de oro (ausencia ≠ incumplimiento, ahora en ambos sentidos) y los niveles Conformance → Strict del ADR-001 —más la registrabilidad que F2 difirió.

✓ Hecho ▸ motor puro contractCheck() + límite ComponentRuntime · registrabilidad + props + atributos + reflect + métodos · methods poblados en la ingestión · spec checks-contract.md + tests

✓ Incr. 2 ▸ observeRuntime ampliado: monta el elemento y observa los slots del shadow DOM → nueva faceta slot en contractCheck (declarado ↔ shadow DOM), con tests node + navegador. Vive en #528 (no en #526). VALIDADO en navegador + calibrado async (espera updateComplete de Lit antes de leer slots/reflect): eliminado el falso contract/reflect que afectaba a ~98 componentes. Además, la ingestión ahora descarta los miembros privados _x del CEM (simetría con publicApiOf) → fuera los falsos contract/method. Eventos: no observables por inspección estática → declarados-only.

✓ Calibración D (sentinel tipado) ▸ probeReflect asignaba un sentinel string ('hanko-probe') a cualquier prop reflejable; en props data-driven (charts, series/links/files array) eso las dejaba como string y el render petaba (series.flatMap is not a function, los ~24 pageerror). Resuelto en 3 capas: (1) inferencia por runtime (typeof/Array.isArray: bool→invertido, number→distinto, array→[], object→{}); (2) tipo declarado del CEM (PropTypeHint {kind, literals} inyectado por tag → enum=primer literal válido ≠ actual); (3) red de captura en observeRuntime (los enums-alias del CEM no traen literales → caen al string y aún petan; ese crash es artefacto del sondeo y Lit lo emite diferido a window → se absorbe con preventDefault envolviendo la fase montada). Efecto (dogfood): diagnósticos 24 → 1 (el único restante es genuino), contract/reflect 71 → 31, sellados 36 → 38. Ver specs/harness.md §Calibración.

F4

Accesibilidad (a11y)

en curso

axe + navegación por teclado + foco + nombre accesible. Pruebas universales: aplican a cualquier componente, declare lo que declare su manifest — F4 no lee el contrato.

✓ Hecho ▸ motor de política puro a11yCheck() + observación A11yObservation · umbral de severidad (failOn) + teclado/foco/nombre exigidos a interactivos · spec checks-a11y.md + tests

✓ Incr. 2 ▸ el harness de a11y (observeA11y, axe inyectado + sondeos de interactividad/teclado/nombre) vive centralizado en #528 y está VALIDADO en navegador (Playwright/chromium) y corrido sobre componentes reales.

◷ Calibración pendiente ▸ 29 componentes fallan a11y; en parte señal real, en parte por montarse VACÍOS sin nombre accesible. Heurísticas v0 (interactividad / nombre / focusVisible) a afinar contra componentes reales.

F5

Resiliencia

en curso

Props basura / vacías, SSR, RTL. El componente no debe romperse ante entradas adversas. También universal, no depende del contrato.

✓ Hecho ▸ motor de política puro resilienceCheck() + observación ResilienceObservation · escenarios obligatorios vs tolerables (optional) · spec checks-resilience.md + tests

✓ Incr. 2 ▸ el harness compartido src/harness/ (las tres observaciones: runtime · a11y · resiliencia) vive en este PR (#528) — VALIDADO en navegador y corrido sobre componentes reales (dogfood/Playwright, ~102 componentes).

✓ Calibración ▸ captura completa de crashes por trial: cada escenario corre en una ventana que escucha window (error + unhandledrejection, con preventDefault) además del rechazo de updateComplete → observeResilience ya no da falsos «sobrevivió» por throws que Lit emite a nivel de ventana. Test de navegador del camino nuevo (hanko-window-thrower). Hallazgo (dogfood, aislado): un montaje adverso-vacío de shibui sobrevive limpio salvo 2 crashers en junk-attrs; los ~24 pageerror de report-full.html dan 0 si se aísla el probe a resiliencia → no son fallos de resiliencia, son artefactos del sentinel string de probeReflect (el patrón X.map is not a function) → ver F3 / calibración D.

◷ Diferido ▸ sembrar datos mínimos por tipo (valid-min) para un escenario duro — se probó y el contrato no mejora (el ruido restante es drift del CEM).

F6

Trust Report + gates de CI

en curso

Reporte de confianza (JSON + HTML) que declara procedencia y cobertura del sello. Gates que fallan el build cuando un componente no cumple su nivel exigido.

✓ Incr. 1 ▸ agregador puro buildTrustReport() —compone Floor + contrato + a11y + resiliencia por componente, con procedencia y regla de oro (capa no evaluada → skipped, no descalifica)— + renderers renderTrustReport{Json,Html} (HTML con marca washi) · spec trust-report.md + tests node. Rama feature/hanko-trust-report.

◐ Incr. 2 ▸ puente en dos etapas cableado: la sonda dogfood/probe-shibui.ts (Etapa 1) corre el harness sobre los componentes vivos de la librería consumidora en chromium → observations.json; el runner src/report/run.ts (Etapa 2) lee esas observaciones + Floor estático y corre los checks puros → las 4 capas. CI (observe → report) publica en hanko-report.web.app en cada main. La sonda vive fuera de src/ (único punto que carga la librería consumidora; el guard de genericidad sigue verde). El harness ya está validado en navegador (Lit async calibrado). Pendiente: el gate duro (fallar el build cuando un componente no cumple su nivel).

✓ Incr. 3 ▸ emisor de issues de GitHub (opt-in): src/report/github-issues.ts (toIssueDrafts puro + syncGithubIssues idempotente: crea/actualiza/cierra · cliente REST con fetch, cero deps) + runner issues-run.ts (script issues, lee trust-report.json; --dry-run). Un issue por componente sin sello, marcador estable como clave de dedupe. No es default: en CI lo gatea force_hanko_issues (workflow_dispatch) → input github_issues de ci-lib. Spec github-issues.md + tests con fake client.

F7

Desacople + publicación npm

en curso

Garantizar que el core no depende de ninguna librería consumidora y publicar @shibui-ui/hanko como paquete independiente.

✓ Desacople ▸ el principio «el core nunca importa la librería consumidora» es ahora un test ejecutable (src/genericity.test.ts): escanea todos los imports y falla si alguno referencia el paquete consumidor o trepa a su carpeta (+ se autovalida). La comunicación sigue siendo solo vía el fichero CEM.

✓ Publicable ▸ barrel público src/index.ts + tsconfig.build.json (emite dist/) + metadata npm (exports/types/files/publishConfig) · spec packaging.md

◐ Diferido ▸ el npm publish real (quitar private + versión + credenciales) y elegir bundler para ESM-Node nativo quedan para cuando el harness esté validado y dogfoodeado.
