# Katachi · 形 · Aesthetic contexts

> **Katachi (形)** significa "forma, configuración". En Shibui UI es la capa que agrupa
> **superficie + efectos + temperatura cromática** en una personalidad visual nombrada,
> propagable a un árbol entero desde un único atributo en cualquier ancestro.

Se activa con `data-katachi="x"` en cualquier elemento contenedor (o vía `<lib-canvas katachi="x">`). Las CSS custom properties propagan por herencia y atraviesan Shadow DOM, así que todos los descendientes adoptan el contexto sin más cableado.

```html
<body data-katachi="kintsugi">
  <lib-card>…</lib-card>            <!-- adopta superficie kintsugi -->
  <lib-button>…</lib-button>        <!-- adopta paleta kaki -->
  <lib-glass-card>…</lib-glass-card><!-- glass silenciado (conflicto) -->
</body>
```

## Cómo activarlo

### 1 · Atributo en contenedor HTML

```html
<body data-katachi="kintsugi">
  <!-- todo el árbol hereda el contexto -->
</body>

<section data-katachi="sabi">
  <!-- solo esta sección adopta sabi -->
</section>
```

### 2 · Wrapper tipado (`<lib-canvas>`)

```html
<lib-canvas katachi="kintsugi" display="block" pad="xl">
  <lib-card>…</lib-card>
</lib-canvas>
```

| Atributo | Valores | Notas |
|----------|---------|-------|
| `katachi` | `'' \| 'wabi' \| 'kintsugi' \| 'sabi' \| 'terminal' \| 'shizen' \| 'celadon'` | Tipado `KatachiId` en TS |
| `display` | `'contents' \| 'block' \| 'flex'` | `contents` = sólo contexto, sin caja |
| `pad` | `'' \| 'lg' \| 'xl' \| '2xl'` | Shortcut para box modes |
| `min-h` | `'' \| 'screen'` | Útil para demo pages a viewport completo |

### 3 · Atributo directo en un custom element

```html
<lib-card data-katachi="celadon">…</lib-card>
```

Selector dual `[data-katachi="x"], :host([data-katachi="x"])` garantiza que ambos patrones funcionan.

## Matriz de compatibilidad

| Katachi | glass | spotlight | kintsugi-border | shadow-brutal |
|---------|-------|-----------|-----------------|---------------|
| **wabi**     | ✅ reforzado | ❌ off | 🔲 compatible | ❌ conflicto |
| **kintsugi** | ❌ off | ✅ reforzado | ✅ reforzado | ❌ conflicto |
| **sabi**     | ❌ off | ❌ off | ❌ conflicto | ✅ nativo |
| **terminal** | ❌ off | ❌ off | ❌ conflicto | ✅ con tinte celadón |
| **shizen**   | 🔲 compatible | ❌ off | 🔲 compatible | 🔲 compatible |
| **celadon**  | 🔲 compatible (water) | ✅ reforzado (water) | 🔲 compatible | ❌ conflicto |

Los efectos marcados como ❌ se **silencian** vía tokens (`--lib-glass-blur-amount: 0px`, etc.), no se prohíben. Un componente que los consume sigue renderizando, simplemente sin el efecto.

---

## Anidamiento

Los katachi se anidan libremente — la regla del descendiente más cercano gana porque cada bloque redefine sus propios tokens semánticos:

```html
<section data-katachi="kintsugi">
  <lib-card>…</lib-card>           <!-- kintsugi -->
  <aside data-katachi="terminal">
    <lib-card>…</lib-card>         <!-- terminal -->
  </aside>
</section>
```

---

## Compatibilidad con `variant=""` explícito

El sistema katachi **nunca pisa una variante explícita**:

```html
<section data-katachi="kintsugi">
  <lib-card>kintsugi (ambient)</lib-card>
  <lib-card variant="washi">washi (override explícito gana)</lib-card>
</section>
```

`:host([variant="washi"])` y `:host(:not([variant]))` son mutuamente exclusivos por construcción, no por especificidad. El `variant=""` explícito siempre tiene la última palabra.
